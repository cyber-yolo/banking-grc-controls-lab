# RA-002 MFA is not phishing-resistant

| Field | Value |
|---|---|
| Control | CTL-001 |
| Requirements affected | REQ-DORA-05 (strong authentication), REQ-RMF-02 |
| Gap | Lab users use the Microsoft Authenticator app (push or code), which can be phished or fatigued; phishing-resistant methods (FIDO2 keys, passkeys, Windows Hello for Business) are not used |
| Reason | No hardware keys in the lab; the aim is to evidence the control logic, not the strongest method |
| Compensating measures | DET-011 (MFA fatigue) and DET-005 (success after failures) |
| What a bank would do | Authentication strength "phishing-resistant MFA" for administrators first, then all staff |
| Decision by | Lab maintainer (acting as risk owner) |
| Date | YYYY-MM-DD |
| Expires | End of the lab campaign |
